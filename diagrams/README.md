# diagrams — схемы занятий

Одна папка на урок. Внутри урока — отдельный файл `.excalidraw` на каждую мысль,
рядом — скрипт, который эту схему собирает, и данные урока.

Ничего не рисуется руками в редакторе: схема = скрипт + данные. Поэтому её можно
поправить в одном месте, пересобрать за секунду и не потерять оформление.

```
diagrams/
├── README.md              этот файл
├── registry.md            реестр схем: все файлы, размеры, есть ли скрипт (собирается сам)
├── blocks.py              переиспользуемые блоки: карточка, стрелка, легенда, проверки
├── render.py              PNG-предпросмотр любой схемы (проверка вёрстки глазами)
├── registry.py            собирает registry.md обходом lesson_*/
├── build_lesson.py        собрать все схемы урока / все уроки (+ обновить реестр)
├── _template/             заготовка нового урока: скопировал, переименовал, правишь
│   ├── data.py            образец файла данных
│   └── 01_example.py      образец схемы со всеми блоками в работе
├── lesson_39/             урок 39 «GROUP BY»
│   ├── 01_group_by_hair.excalidraw       один признак: 3 группы, count/avg, NULL
│   ├── 02_group_by_hair_eye.excalidraw   два признака: 5 групп со стрелками
│   ├── 01_group_by_hair.py … 02_group_by_hair_eye.py   скрипты этих схем
│   ├── data.py               6 учебных строк + расчёт групп (агрегаты не вписаны руками)
│   └── _source/              архив: исходник (40 эл.) и предыдущие варианты v2/v3
└── lesson_40/             урок 40 «связи между таблицами»
    ├── 00_map.excalidraw      карта: в каком порядке читать шесть схем
    ├── 01_pk.excalidraw       первичный ключ
    ├── 02_fk_o2m.excalidraw   внешний ключ и «один ко многим»
    ├── 03_o2o.excalidraw      «один к одному»
    ├── 04_m2m.excalidraw      «многие ко многим»
```

## Собрать

```bash
cd diagrams
python build_lesson.py               # все уроки + обновить registry.md
python build_lesson.py lesson_40     # только урок 40
python lesson_40/02_fk_o2m.py        # только одна схема
python registry.py                   # только пересобрать реестр
python render.py lesson_40/02_fk_o2m.excalidraw preview.png   # посмотреть глазами
```

`build_lesson.py` возвращает код 1, если хоть одна схема не прошла проверки.
Превью в PNG — приблизительное (PIL + те же шрифты); оно для проверки вёрстки,
а не вместо Excalidraw.

## Реестр схем

`registry.md` — список всего, что лежит в `diagrams/`: имя файла, сколько элементов
и стрелок, габарит, есть ли рядом скрипт (то есть пересобирается файл или заморожен)
и заголовок схемы. В конце — раздел «Требуют скриптов».

Реестр **не правится руками**: `python registry.py` обходит `lesson_*/` и `_source/`,
читает каждый `.excalidraw` и перезаписывает таблицу. `build_lesson.py` делает это
в конце каждого запуска, так что реестр всегда соответствует диску.

## Новый урок за пять минут

1. `cp -r _template lesson_41`
2. В `lesson_41/data.py` — строки своих таблиц. Все схемы урока берут данные только отсюда.
3. Переименуй `01_example.py` → `01_<тема>.py`, поправь `OUT`, заголовок, раздел, карточки.
4. Нужна вторая схема — скопируй первый файл, поменяй `OUT` и содержимое.
5. `python build_lesson.py lesson_41` → должно быть `structural checks: PASS`.
6. Карту урока (`00_map`) удобно сделать первой: она задаёт порядок чтения.

## Что умеет `blocks.py`

### Сцена и служебное

| Метод | Что делает |
|---|---|
| `Scene()` | новая сцена. Все элементы копятся в ней, id уникальны автоматически |
| `s.save(path)` | записывает `.excalidraw` и печатает отчёт проверок; возвращает список проблем |
| `s.checks()` | сами проверки (см. ниже), если нужен отчёт без записи файла |

### Заголовки и пояснения

| Метод | Что делает |
|---|---|
| `s.title(main, sub)` | заголовок схемы (36 px) + подзаголовок; возвращает y, где можно продолжать |
| `s.section(x, y, num, title, sub)` | номер раздела с цветной полоской + название + пояснение; возвращает y под карточки |
| `s.note(ident, text, x, y, fs, color)` | строка вывода под схемой |
| `s.label(ident, text, x_center, y, fs, color)` | подпись, отцентрованная по `x_center`: `1 : N`, `ON ...` |
| `s.band(ident, x, y, w, text)` | цветная плашка-определение на всю ширину |
| `s.chip(ident, x, y, text, fill)` | маленькая плашка с подписью |
| `s.legend(x, y)` | расшифровка ролей столбцов (PK / FK / UNIQUE / NOT NULL) |

### Карточки

`s.card(prefix, x, y, title, cols, rows, bars=None, header=CARD_HDR, colhead=True, row_h=32)`

* `cols` — `[('имя столбца', минимальная ширина)]`; ширина каждого столбца считается
  **по содержимому**, вручную подгонять не нужно;
* `rows` — `[[ячейка, ...]]`, текст моноширинный;
* `bars` — `{индекс столбца: цвет полоски}`, роли: `PK`, `FK`, `UQ`, `NN`;
* `colhead=False` — карточка без строки названий столбцов (для панелей и определений);
* возвращает словарь: `x`, `y`, `w`, `h`, `right`, `bottom`, `rows` (y-центр каждой строки) —
  по нему удобно ставить стрелки.

| Метод | Что делает |
|---|---|
| `s.code(prefix, x, y, [строки], title='SQL', width=380)` | панель кода: без шапки столбцов, текст в цвет, моноширинный |
| `s.frame(ident, x, y, w, h, label=None)` | рамка-панель вокруг группы карточек |

### Стрелки

`s.arrow(ident, pts, color, sw=2.2, both=False, lane=None)`

* `pts` — точки ломаной; `lane=x` сам вставит вертикальный коридор между концами
  (стрелка от строки к строке идёт «ступенькой»);
* `both=True` — стрелка в обе стороны (для `1 : 1`);
* каждая стрелка получает свою дорожку: если у `lane` разные `x`, линии не слипаются.

### Палитра: цвет = роль

| Константа | Значение | Где применять |
|---|---|---|
| `PK` / `FK` / `UQ` / `NN` | сиреневый / оранжевый / зелёный / голубой | полоски столбцов |
| `CARD_HDR` | светло-синий | заливка шапки карточки-таблицы |
| `NOTE` | жёлтый | карточка-запрос, плашки-определения |
| `OUT_FILL` | зелёный | карточка результата |
| `CODE_BG` | серый | панель кода |
| `ORANGE`, `ORANGE_T` | оранжевый | стрелки FK-связи / текст того же цвета |
| `GREEN`, `GREEN_T` | зелёный | стрелки «нашлось», `1 : 1` |
| `RED` | красный | стрелки «не нашлось», предупреждения |
| `BLUE` | синий | стрелки JOIN, код |
| `VIOLET` | сиреневый | номер раздела, акценты |
| `GROUP_COLORS[i]` | 5 пар (заливка, цвет) | «одна группа = один цвет»: шапка карточки и стрелка (схемы группировки) |
| `TEXT` / `MUTED` | почти чёрный / серый | основной текст / пояснения |

Буквы с `_T` — те же цвета, но затемнённые: обычные оранжевый и зелёный годятся
для линий, а для текста на белом не проходят по контрасту.

### Шрифты

`SANS = 2` (Arial) — заголовки и пояснения; `MONO = 3` (Cascadia Code) — таблицы и код.
Рукописный шрифт Excalidraw не используется: таблицы, выровненные пробелами, в нём разъезжаются.

## Правила, которых держатся схемы

1. **Один файл — одна мысль.** Экран ≈1400×900. Если мыслей две — два файла.
2. **Данные дублируются в картинке, но живут в одном файле.** Каждая схема
   самодостаточна (её можно отдать одну), а строки все берут из `data.py` урока.
   Поэтому опечатка правится один раз.
3. **Стрелка — от строки к строке,** а не «между блоками»: тогда видно, кто на кого
   ссылается. У каждой стрелки своя вертикальная дорожка.
4. **Цвет означает ровно одно:** роль столбца (полоска) или тип связи (стрелка).
   Легенда стоит на каждой схеме.
5. **Подписи короткие.** Длинное объяснение — это не диаграмма, а конспект.
6. **Порядок чтения сверху вниз, слева направо.** Если схема требует объяснения
   «смотри сюда, потом туда» — скорее всего нужна карта (`00_map`).

## Проверки (что именно ловит `save()`)

| Проверка | Провал, если |
|---|---|
| уникальность id | два элемента с одинаковым id |
| привязка подписей | текст со `containerId` не влезает в блок или нет обратной привязки |
| текст в карточке | подпись вылезает за границы своей карточки |
| контраст текста | меньше 4.5 : 1 к фону под ним |
| контраст стрелки | меньше 3 : 1 к белому |
| стрелка и блок | стрелка проходит сквозь карточку |
| пересечения стрелок | **предупреждение**, не провал: печатается число |

Пересечения — это диагностика: 2–3 пересечения в схемах про связи нормальны
(строки идут вразнобой), а вот 10+ значит «перегрузил, подумай о другом виде».

## Урок 42 — что в схемах

Тема: **оконные функции**. Все десять схем — одни и те же восемь героев
(таблица `heroes`): 480 появлений, среднее 60. Меняется только вопрос.

| Файл | О чём | Что видно |
|---|---|---|
| `00_map` | карта урока | девять ступеней в двух блоках: агрегаты в окне и функции окна |
| `01_groupby_loses_rows` | зачем окно | 8 строк → 3: имена пропали (на базе 16 376 → 4) |
| `02_over_partition` | `PARTITION BY` | скобки по лагерям: 8 на входе — 8 на выходе |
| `03_over_empty` | `OVER ()` | одна скобка на всю таблицу: у всех 60, разница от +40 до −40 |
| `04_two_windows` | два окна в строке | Халк: −20 от всех, но −40 от своих; Жел.чел: 0 и +20 |
| `05_count_by_eye` | окно и `WHERE` | голубые 3, зелёные 4; строка без цвета убрана до окна |
| `06_running_total` | `ORDER BY` в окне | ступеньки 220 → 420 → 480 |
| `07_ranks` | три функции ранжирования | `1 1 3 4 5 5 5 8` против `1 1 2 3 4 4 4 5` |
| `08_top_per_group` | топ в группе | три окна по годам и шаг `WHERE rank_in_year = 1` |
| `09_lag_lead` | `LAG` и `LEAD` | сосед сверху и сосед снизу; у краёв шеренги `NULL` |

Три вещи, которые стоит знать про этот урок:

* **В наборе нарочно есть равные значения** (100 у двоих, 40 у троих): на данных
  прошлых уроков все значения разные, и `RANK` с `DENSE_RANK` там просто не отличаются.
* **Ни одного числа руками.** `data.py` строит базу в `:memory:` и прогоняет запросы:
  средние, места и итоги приходят из SQLite, поэтому картинка не может разойтись
  с данными. Проверка: `python lesson_42/data.py` печатает все наборы.
* **Есть защита от немой ошибки.** Если в каком-то году двое претендуют на первое
  место, `data.py` падает: иначе схема 08 нарисовала бы одного победителя и соврала.

За рамками урока остались `RANGE` и `ROWS BETWEEN`: там рамку окна задают явно,
и это следующая тема. Схема 06 уже показывает поведение по умолчанию — все ровесники
по году получают один и тот же итог.

## Урок 41 — что в схемах

Тема: **типы JOIN в SQLite**. Все шесть схем — одна и та же база и один и тот же
вопрос «какие строки остаются в ответе», меняется только тип JOIN.

| Файл | О чём | Что видно |
|---|---|---|
| `00_map` | карта урока | шесть типов, порядок чтения, с какой версии есть `RIGHT`/`FULL` |
| `01_inner` | `JOIN` (INNER) | пары остались, «Бесы» и Толстой перечёркнуты красным |
| `02_left` | `LEFT JOIN` | зелёная шапка у `books`; «Бесы» пунктиром ведут в свою строку с `NULL` |
| `03_right` | `RIGHT JOIN` | зелёная шапка у `authors`; Толстой пунктиром ведёт в строку с `NULL` |
| `04_full` | `FULL OUTER` | обе шапки зелёные, 5 строк: 3 пары + «Бесы» + Толстой |
| `05_cross` | `CROSS JOIN` | 4 × 3 = 12 строк, в SQLite это ещё и способ запретить перестановку таблиц |
| `06_natural` | `NATURAL JOIN` | соединил по общему имени `id` — и пара получилась бессмысленной |

Данные: `authors` 3 строки, `books` 4 строки (у «Бесов» `author_id` пустой),
`sales` 3 строки для схемы про `NATURAL`.

Схемы этого урока — **готовые `.excalidraw`, без скриптов**. Сборки у них нет:
правили их руками в редакторе (в том числе `author_id` у «Бесов»), а старые
скрипты `data.py` / `joinbits.py` / `0N_*.py` удалены в Корзину, чтобы случайная
пересборка не откатила правку.

Что стоит знать про эти схемы:

* **Четыре краски, и каждая значит одно:** зелёная шапка карточки — таблица попала
  в результат целиком (это единственное видимое отличие LEFT/RIGHT/FULL);
  красная черта поперёк строки — строка выпала; красный `NULL` — строка в ответе
  есть, данных с этой стороны нет; красный пунктир — «пары не нашлось», ведёт
  из строки прямо в её строку результата.
* **Сквозной счётчик строк.** В таблицах 7 строк, подпись результата говорит
  `3 из 7`, `4 из 7`, `5 из 7`, `12` — цифры сравниваются между схемами.
* **Результат стоит справа от таблиц, а SQL — под ним:** иначе схема вырастала
  за 900 px и на проекторе её пришлось бы уменьшать (правило 1). Самое большое —
  1139 × 883.
* **Правка — только в редакторе.** Цифры на картинках больше не пересчитываются
  автоматически: если менять пример, менять надо все шесть схем руками
  и согласованно (иначе `3 из 7` разойдётся с картинкой).

## Урок 40 — что в схемах

| Файл | О чём | Что видно |
|---|---|---|
| `00_map` | карта урока | шесть ступеней и порядок чтения |
| `01_pk` | первичный ключ | 4 поста с 4 написаниями категории → запрос находит 1 строку из 4 |
| `02_fk_o2m` | внешний ключ, O2M | 3 поста ссылаются на 2 категории, подпись `1 : N`, `ON DELETE RESTRICT` |
| `03_o2o` | «один к одному» | студент и билет, `UNIQUE` + `NOT NULL`, стрелка в обе стороны |
| `04_m2m` | «многие ко многим» | пост ↔ связка ↔ тег, `1 : N` и `N : 1`, составной ключ |
| `05_join_o2m` | JOIN | `ON` по внешнему ключу, таблица результата, SQL |
| `06_join_m2m` | JOIN через связку | два `JOIN`, результат «пост + тег», SQL |

Данные урока (`lesson_40/data.py`): посты 1–4, категории «Высокие технологии» и
«Программирование», теги «Маск» и «Python», пары связки (1,1), (1,2), (2,2),
студент «Иванова» с билетом. Написание таблиц правильное: `categories`, `hashtags`.

## Урок 39 — что в схемах

Тема: `GROUP BY` на шести учебных строках (`MarvelCharacters`): Тор, Жел. чел, Чел-пук,
Кэп, Рассамаха, Шторм; признаки — `hair`, `eye`, `appearances` (у Тора `NULL`).

| Файл | О чём |
|---|---|
| `01_group_by_hair.excalidraw` | один признак: три группы, `count(*)`, `count(appearances)`, `avg`, отдельная карточка на группу |
| `02_group_by_hair_eye.excalidraw` | два признака: пять групп, от каждой строки стрелка в свою группу, цвет = номер группы |
| `_source/group_by.excalidraw` | исходная схема из 40 элементов (архив, байт в байт) |
| `_source/group_by_v2.excalidraw`, `_source/group_by_v3.excalidraw` | предыдущие варианты (135 и 131 элемент), сделаны разовыми скриптами — архив |

Что важно в этих схемах:

* **Агрегаты считаются, а не вписаны.** `data.py` сам считает `count(*)`, `count(appearances)`
  и `avg`; поэтому цифры на картинке не могут разойтись с данными. В старой схеме
  среднее для «Блонд» было 1000 вместо 2000 — `NULL` не считается, а не равен нулю.
* **Два признака — пара, а не 3 × 3.** Пять групп: «Блонд · Голубые», «Брюнет · Карие»,
  «Брюнет · Зеленые», «Каштан · Карие», «Каштан · Зеленые».
* **Данные учебные.** Это не выгрузка из `marvel_normal.db`: прозвища и числа подобраны
  для занятия (в настоящей базе набор первых шести строк другой). Проверить расчёт:
  `python lesson_39/data.py`.

## `_source` — исходники

Там лежит то, из чего собирался урок: ваша схема «6 тем на одном листе» (156 элементов,
3004 × 5540) и промежуточный вариант в две колонки. Файлы не пересобираются скриптами —
это архив для сверки. Опечатки `categoires` и `hastags` в исходнике исправлены на месте:

## Ограничения

* Настоящий рендер библиотекой Excalidraw и импорт в плагин Obsidian не проверялись:
  локальной копии библиотеки нет. Превью собирается своим рендером на тех же шрифтах.
* Нужны установленные шрифты Arial и Cascadia Code (Windows — есть из коробки).
* `blocks.py` считает ширину текста через PIL, поэтому в карточках заложен запас 8 px:
  если в новой схеме текст всё же касается границы, увеличь минимальную ширину столбца.
